# Agent Note: 宿主持有的 UI 展示选择

Status: implemented

[English](2026-09-06-host-owned-ui-presentation.md) | 中文

## 问题

硬编码可见性与单一设置布局会让可复用的客户端包依赖某个宿主的产品选择。维护宿主专属源码改动也会增加这些包演进时的冲突。

## 决策

客户端插件提供通用展示选项，组合 Profile 提供产品默认值。现有 Host 设置提供方与 Client 设置镜像传递这些值，不建立第二套配置通信。Schema 默认显示统计、命令入口、会话搜索和分组控件。显式保存的字段覆盖 Profile 基础值，包括对话显示偏好。这些值控制展示，不控制命令、统计、搜索或已存储分组的访问能力。

设置外壳支持 `modal` 和 `page`，共享导航、内容 slot 和查看状态。默认值为 `modal`；[全窗口页面决策](../feature/2026-09-04-full-window-settings-page.zh.md) 继续约束可选页面布局。关闭文案 slot 接收展示类型，供注册方区分关闭弹窗与返回应用。

品牌名称、服务地址、内置业务组合包和产品专属默认值属于组合应用，不属于通用客户端包。极简对话、批注、提交上下文与会话重命名保持为可独立使用的能力。

## 考虑过的替代方案

**保留宿主专属源码补丁或 CSS 隐藏。** 这些方式掩盖受支持的默认行为，并将宿主维护耦合到组件内部实现。

**建立第二套设置外壳或配置通信。** 现有分区 slot 和设置镜像已经提供内容组合、校验与重连行为。重复实现会增加生命周期与焦点归属，却没有新的消费方需求。

## 后果

Profile 无需替换组件即可选择展示方式。控件等待首次设置读取，避免连接启动期间显示另一套默认值。非回环客户端保留现有仅内存偏好行为与通用默认值。外观设置不是安全策略；显式用户文档可覆盖 Profile 默认值。宿主组合测试验证默认值、配置值、校验及已有用户偏好优先；组件测试验证可见性和两种设置关闭路径。
