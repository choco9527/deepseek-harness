# Agent Note: 显式启动工作区路径迁移

Status: implemented

[English](2026-09-18-workspace-path-relocation.md) | 中文

## 问题

Desktop 产品目录变更必须保留工作区身份和会话分组。仅建立文件系统别名会改变会话 cwd 的规范路径，而工作区记录仍保存原规范路径，导致已记录会话被过滤。重写已发布的会话代际文件会违反其不可变要求。

## 决策

workspace 插件在启动时接受宿主显式提供的 `pathRelocations`。宿主在启动注册表之前完成物理迁移、保留别名并排除其他写入者。两个路径必须解析到同一目录。注册表按最具体的映射解析子目录，在写入前检查全部结果路径是否冲突，并在索引会话头和发布实体之前仅更新受影响记录。工作区 ID、会话账本、注册表顺序和归档状态保持不变。每条记录原子写入；重启继续部分更新，不重置已经更新的记录。

这仅扩展了[领域存储提案](../../proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.zh.md)中的路径处理；存储设计和归属账本的依据仍独立有效。[workspace README](../../../../packages/workspace/workspace/README.zh.md)负责配置与失败语义。

## 考虑过的替代方案

**仅建立别名：** 会话 cwd 的规范路径改变，但存储的工作区路径不变，历史因此从分组中隐藏。

**重写会话日志：** 改变不可变的历史记录，还可能破坏物理日志寻址。保留别名使已记录 cwd 和产物引用可用，无需重写日志。

**从缺失路径推断迁移：** 无法区分有意迁移和暂时不可用的存储。只有显式且经过物理验证的映射才改变元数据。

## 影响

宿主继续负责退出、文件系统迁移、锁与别名生命周期。注册表不合并冲突工作区，也不提供运行时目录移动。记录字段和事件字节不变，因此领域版本与 Session 格式版本均不变。

## 验证

工作区测试覆盖身份、顺序、归档、嵌套路径、冲突拒绝、显式启用、重启幂等和记录写入中断。使用 JSON 存储及 JSONL 持久化的真实 Loader 组合在目录迁移后重新打开录制会话，并验证日志字节不变。打包版 Desktop 启动与 Windows junction 行为仍需宿主独立验收。
